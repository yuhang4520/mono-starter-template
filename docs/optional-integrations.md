# 第四批：可选扩展接入

本轮没有安装或实现以下供应商模块。它们是扩展设计约定，默认模板不依赖支付账号、短信、模型服务或转码平台。

## 验证码与身份验证

在 Admin 认证 HTTP 边界和 API 注册/登录入口加入服务端验证；供应商通过接口注入，公有 scene/app 标识与私钥分别配置。原生 WebView 桥接需使用短期、一次性、绑定请求用途的 challenge，消费过程原子化。验证码成功不证明手机号所有权；需要手机号可信身份时另接短信或可信身份提供者。

验收应包括绕过前端直接调用、过期/重复消费、用途或手机号不匹配、供应商超时。不能只在登录按钮前做浏览器校验。当前组织和平台管理写操作集中于有审计和实时授权的服务入口，不应为接验证码重新开放被禁用的管理旁路。

## 异步任务与补偿

在独立业务包中定义任务状态、幂等键、attempts、nextAttemptAt、leaseToken/leaseExpiresAt、最后错误码；使用唯一约束防重复入队，领取和完成需校验租约所有者。外部请求放在短事务之外，失败按可重试/需人工处理分类，设置退避和上限。队列可以先用 PostgreSQL，再按吞吐需求接消息队列。

CronJob 禁止同类任务重叠，设置超时和历史保留；修改 CronJob 不会替换已经运行的 Job。验收重复事件、进程崩溃、租约超时、并发领取、旧 worker 晚到和死信重放。不要把支付专属交易表直接当成通用任务模型。

## AI 服务

通过服务端适配器管理模型、结构化输出校验、超时、请求 ID、用量记录与脱敏日志。共享包对外提供业务结果而非直接暴露 SDK response。外部模型调用期间不持有数据库事务或行锁；提交结果时短事务重新校验源数据版本及额度，防止旧结果覆盖新数据、重复扣费。

如要严格限制同时消耗，增加明确的额度预留/释放状态机；仅调用前检查余额无法保证并发调用都不产生供应商费用。验收超时、畸形输出、重试、重复结果、用户取消与源数据变化。模板不包含 RAG、向量库或模型厂商密钥。

## 金额与支付

金额保存币种与整数最小单位，显示格式化与服务端入账转换分离；原生缺少 Intl 时用展示降级，不用降级规则核算真实交易。订单、支付交易、事件/退款和权益账本分别建模，唯一约束与事务承担幂等性。

支付成功以服务端验签和渠道核验为依据，通知先持久化，权益发放与处理状态保持原子一致；客户端负责恢复和展示。苹果、微信、支付宝的密钥、沙箱环境、回调与退款规则分别适配，按项目选择渠道。不要复制教学权益或当前 Wabash 的学习卡/学生关联字段。

## 音视频

当前模板已支持个人私有图片/PDF 上传。扩展音视频时添加任务状态、上传取消/重试、大小与时长限制、私有播放签名和转码通知幂等处理；大文件优先采用受限的临时上传凭证或分片上传，避免应用服务长时间缓存整个文件。

MPS/队列/死信/RRSA 等放在可选基础设施中，bucket、region、角色 ARN、回调地址必须配置化。凭据提供者显式区分本地静态密钥与生产工作负载身份；不要让无关环境变量中的静态密钥覆盖工作负载角色。真机验证权限、后台上传、弱网、存储清理和播放兼容性。
